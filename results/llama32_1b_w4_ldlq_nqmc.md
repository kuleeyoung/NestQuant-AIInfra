# Llama-3.2-1B：block-LDLQ NQMC 导出与独立回载

## 结论

方向一已经完成。项目把 train64 校准得到的 E8 block-LDLQ 最终码字写入真实 NQMC 文件，并在不提供 Hessian 的独立进程中回载。内存量化、导出后立即回载、独立回载三条路径的完整 WikiText-2 PPL **精确一致**，均为 `10.276132955046`。

| 路径 | 是否需要 Hessian | 完整 WikiText-2 PPL |
|---|---:|---:|
| train64 LDLQ 内存质量仿真 | 编码时需要 | 10.276133 |
| LDLQ 编码 → NQMC → 立即回载 | 编码时需要 | 10.276133 |
| 已有 NQMC 独立回载 | **不需要** | 10.276133 |

BF16 PPL 为 `9.757045`，普通 NestQuant W4 为 `11.202577`。block-LDLQ 保留了此前的质量收益，消除了普通 W4 到 BF16 差距的 `64.09%`。

## 校准证据

- 校准集：`WikiText-2 train`，固定 revision `b08601e04326c79dfdd32d625aee71d232d685c3`。
- 校准规模：64 × 2048 = `131,072` token。
- 选中 token SHA-256：`7dcba79b76b0e185ab48d7e27697db01da6345122b6fd0f000a3d64ae9229db3`。
- Hessian：5 个文件、65 份唯一统计，共 `5,117,078,469` B（4.77 GiB）。
- Hessian 只用于离线 LDLQ 编码；NQMC 解码不读取 Hessian。NQMC 内保存 residue code、beta index、行范数和可复现 dither RNG 状态。

## 工程边界

NQMC 是真实低比特**存储**格式，但当前加载后会解码为浮点权重并执行 BF16 Linear。该结果证明文件可独立保存、校验、回载并保持 PPL，尚未证明低比特常驻显存或推理加速。完整原始 manifest 和大模型文件位于 `results/raw/`，被 Git 忽略；本文件与同名 JSON 是可提交的核验摘要。
