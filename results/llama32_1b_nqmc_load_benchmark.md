# Llama-3.2-1B NQMC 流式回载工程基准

本实验只比较同一个 1,044,557,140 字节 NQMC 文件的两种回载实现，不运行 WikiText-2、PIQA、HellaSwag 或推理吞吐测试。模型固定为 `meta-llama/Llama-3.2-1B` revision `4e20de362430cd3b72f300e6b0f18e50e7166e08`，环境为 WSL2、RTX 5070、PyTorch `2.14.1+cu130`。每种方式在独立进程中运行 3 次。

| 回载方式 | NQMC 阶段耗时，均值±样本标准差 | 基座模型加载后 RSS 峰值增量 | CUDA 峰值 allocated |
|---|---:|---:|---:|
| 旧实现：整文件、完整容器、完整恢复 state dict 同时保留 | 28.14±4.67 s | 3.289 GiB | 7.147 GiB |
| 新实现：分块校验、逐记录验证与写入 | 39.95±3.06 s | 1.467 GiB | 3.133 GiB |

三次运行均值显示，流式路径将主机 RSS 峰值增量降低 **55.38%**，将 CUDA 峰值 allocated 降低 **56.16%**；NQMC 阶段耗时增加 **41.98%**。三次运行的 CUDA 峰值在各自方式内完全一致；RSS 增量的样本标准差分别约 1.81 MiB 和 3.78 MiB。新增耗时来自完整 payload 校验以及写入前的逐记录事务式验证。格式、state-dict 名称、shape、dtype、beta 约束或 alias 不兼容时，模型不会停留在半加载状态。

这是加载阶段工程基准，适合证明“定位并降低模型回载瞬时内存，同时量化时间代价”。它不证明推理显存降低、低比特权重在 GPU 常驻、INT4 kernel 加速或模型质量保持；当前回载结束后仍由浮点 Linear 执行。六份原始机器可读输出保存在被 Git 忽略的 `results/raw/`。
